## 一、正常流程测试

### T1：项目申报 — 完整填写并提交

- **对应需求：** F2
- **前置条件：** 用户已登录，有项目负责人角色
- **操作步骤：**
  1. 进入"科创项目管理 > 项目库"页面
  2. 点击"新建"按钮
  3. 填写所有必填字段：项目编号（如 KX2026080001）、项目名称（如"智能客服系统研发"）、项目类型（选择"新产品研发"）、项目级别（选择"公司级"）、申请部门（选择部门）、项目负责人（选择人员）、预计开始/结束日期、预算金额
  4. 填写项目背景、技术方案、预期成果
  5. 点击"保存"
- **预期结果：**
  - 保存成功，页面跳转到项目详情页
  - 项目状态显示为"草稿"
  - 数据库 uf_kc_project 表新增一条记录
- **测试方式：** 手动验证 + SQL 查询确认数据

### T2：项目申报 — 保存草稿

- **对应需求：** F2
- **前置条件：** 用户已登录
- **操作步骤：**
  1. 进入新建页面，只填写项目名称
  2. 点击"保存"（不提交）
- **预期结果：**
  - 保存成功，项目状态为"草稿"
  - 在项目库列表中可看到该记录
  - 不出现在审批列表中
- **测试方式：** 手动验证

### T3：项目申报 — 提交进入技术评审

- **对应需求：** F2, F3
- **前置条件：** 已保存草稿
- **操作步骤：**
  1. 打开草稿项目
  2. 补充所有必填字段
  3. 通过流程引擎提交
- **预期结果：**
  - 项目状态变为"需求待评审"
  - 技术评审人收到待办通知
- **测试方式：** 手动验证 + 检查待办通知

### T4：技术评审 — 评审通过

- **对应需求：** F3
- **前置条件：** 有状态为"需求待评审"的项目
- **操作步骤：**
  1. 技术评审人打开待办
  2. 查看项目全部信息
  3. 填写评审意见（如"方案可行，建议立项"）
  4. 点击"通过"
- **预期结果：**
  - 项目状态变为"领导审批中"
  - 评审意见已保存
  - 审批领导收到待办通知
- **测试方式：** 手动验证

### T5：领导审批 — 批准立项

- **对应需求：** F4
- **前置条件：** 有状态为"领导审批中"的项目
- **操作步骤：**
  1. 审批领导打开待办
  2. 查看技术评审意见
  3. 填写审批意见
  4. 点击"批准"
- **预期结果：**
  - 项目状态变为"已立项"
  - 项目负责人收到通知
  - 项目进入开发执行阶段
- **测试方式：** 手动验证

### T6：开发执行 — 更新进度和里程碑

- **对应需求：** F5
- **前置条件：** 有状态为"已立项"的项目
- **操作步骤：**
  1. 项目负责人打开项目编辑页面
  2. 更新项目进度为 50%
  3. 进入"里程碑管理"，新增里程碑节点（名称："V1.0开发完成"，计划日期：2026-12-31）
  4. 更新已有里程碑的实际完成日期
  5. 点击"保存"
- **预期结果：**
  - 项目进度更新为 50%
  - 里程碑新增成功
  - 里程碑实际完成日期已更新
- **测试方式：** 手动验证 + SQL 查询 uf_kc_milestone 表

### T7：验收结项 — 提交验收并通过

- **对应需求：** F6
- **前置条件：** 有状态为"开发中"的项目
- **操作步骤：**
  1. 项目负责人在项目编辑页面填写验收信息：
     - 成果物清单："设计文档、源代码、测试报告"
     - 实际花费：150000.00
     - 验收自评总结："项目按期完成，各项指标达标"
  2. 通过流程引擎提交验收
  3. 验收评审人评审后点击"通过"
- **预期结果：**
  - 提交后项目状态变为"验收中"
  - 通过后项目状态变为"已结项"
  - 所有字段变为只读
- **测试方式：** 手动验证

### T8：项目库 — 筛选和搜索

- **对应需求：** F1
- **前置条件：** 数据库中有多条不同状态/类型的项目
- **操作步骤：**
  1. 进入"项目库"页面
  2. 在快捷搜索栏输入项目名称关键词
  3. 选择"项目状态"筛选"开发中"
  4. 选择"项目类型"筛选"新产品研发"
  5. 清除所有筛选条件
- **预期结果：**
  - 输入关键词后列表实时过滤
  - 选择"开发中"后只显示状态为开发中的项目
  - 组合筛选后显示同时满足条件的项目
  - 清除后恢复显示全部项目
- **测试方式：** 手动验证

### T9：里程碑列表 — 查看和筛选

- **对应需求：** F5
- **前置条件：** 有多个里程碑记录
- **操作步骤：**
  1. 进入"里程碑管理"页面
  2. 通过"关联项目"浏览框选择某个项目
  3. 筛选"里程碑状态"为"已完成"
- **预期结果：**
  - 只显示所选项目下已完成的里程碑
  - 列表按"计划完成日期"升序排列
- **测试方式：** 手动验证

## 二、异常流程测试

### T10：技术评审 — 评审驳回

- **对应需求：** F3
- **前置条件：** 有状态为"需求待评审"的项目
- **操作步骤：**
  1. 技术评审人打开待办
  2. 填写评审意见："技术方案不成熟，需要补充详细设计"
  3. 点击"驳回"
- **预期结果：**
  - 项目状态变回"草稿"
  - 项目负责人收到退回通知
  - 评审意见已保存，项目负责人可查看
- **测试方式：** 手动验证

### T11：技术评审 — 不填意见直接提交

- **对应需求：** F3
- **前置条件：** 技术评审人打开待评审项目
- **操作步骤：**
  1. 不填写评审意见
  2. 点击"通过"或"驳回"
- **预期结果：**
  - 系统提示"评审意见为必填项"
  - 无法提交
- **测试方式：** 手动验证

### T12：领导审批 — 驳回并注明原因

- **对应需求：** F4
- **前置条件：** 有状态为"领导审批中"的项目
- **操作步骤：**
  1. 审批领导打开待办
  2. 填写驳回原因："预算超出部门年度计划"
  3. 点击"驳回"
- **预期结果：**
  - 项目状态变回"草稿"
  - 项目负责人收到退回通知
  - 驳回原因可查
- **测试方式：** 手动验证

### T13：验收 — 验收不通过退回开发

- **对应需求：** F6
- **前置条件：** 有状态为"验收中"的项目
- **操作步骤：**
  1. 验收评审人打开待办
  2. 填写验收意见："核心功能未实现，需继续开发"
  3. 点击"不通过"
- **预期结果：**
  - 项目状态变回"开发中"
  - 项目负责人收到退回通知
  - 验收意见已保存
- **测试方式：** 手动验证

### T14：验收 — 预算偏差超过30%未填原因

- **对应需求：** F6
- **前置条件：** 项目预算 100000，准备提交验收
- **操作步骤：**
  1. 填写实际花费为 140000（偏差 40% > 30%）
  2. 不填写"预算偏差原因说明"
  3. 提交验收
- **预期结果：**
  - 系统提示"预算偏差超过30%，必须填写原因说明"
  - 无法提交
- **测试方式：** 手动验证（注：此校验需在流程 Action 中实现，建模引擎本身不支持）

### T15：项目开发中 — 发起终止申请

- **对应需求：** F5
- **前置条件：** 有状态为"开发中"的项目
- **操作步骤：**
  1. 项目负责人发起终止申请
  2. 审批领导审批"批准终止"
- **预期结果：**
  - 项目状态变为"已终止"
  - 项目不可再编辑
- **测试方式：** 手动验证

- **操作步骤：**
  1. 填写预计开始日期：2026-12-01
  2. 填写预计结束日期：2026-06-01
  3. 点击"保存"
- **预期结果：**
  - 系统提示"预计结束日期必须晚于预计开始日期"
  - 无法保存
- **测试方式：** 手动验证（注：此校验需在流程 Action 中实现）

### T17：预算金额为0的项目

- **对应需求：** F6
- **前置条件：** 打开新建页面
- **操作步骤：**
  1. 填写预算金额为 0
  2. 正常填写其他必填字段
  3. 保存并提交
  4. 验收时填写实际花费为 0
- **预期结果：**
  - 预算为 0 的项目正常创建
  - 验收时实际花费为 0，不触发偏差校验
- **测试方式：** 手动验证

### T18：同一人负责多个项目

- **对应需求：** F1

- **操作步骤：**
  1. 以用户 A 登录
  2. 进入"项目库"页面
  3. 查看列表
- **预期结果：**
  - 能看到全部 3 个项目
  - 按负责人筛选"用户 A"后只显示这 3 个项目
- **测试方式：** 手动验证

### T19：已终止项目不可恢复

- **对应需求：** F3, F5
- **前置条件：** 有状态为"已终止"的项目
- **操作步骤：**
  1. 打开已终止项目
  2. 尝试编辑项目信息
  3. 尝试重新提交
- **预期结果：**
  - 项目所有字段只读
  - 无法编辑、无法提交
  - 如需重启，需重新创建新项目
- **测试方式：** 手动验证

### T20：已结项项目数据只读

- **前置条件：** 有状态为"已结项"的项目
- **操作步骤：**
  1. 打开已结项项目
  2. 尝试修改任何字段
- **预期结果：**
  - 所有字段变为只读
  - 无法修改
- **测试方式：** 手动验证

### T21：草稿项目仅创建者可见

- **对应需求：** F1
- **前置条件：** 用户 A 创建了草稿项目，用户 B 也登录了系统
- **操作步骤：**
  1. 以用户 B 登录
  2. 进入"项目库"页面
  3. 查看是否能看到用户 A 的草稿项目
- **预期结果：**
  - 用户 B 看不到用户 A 的草稿项目
  - 用户 A 能看到自己的草稿项目
  - 项目管理员能看到所有草稿
- **测试方式：** 手动验证

### T22：里程碑延期标记

- **对应需求：** F5
- **前置条件：** 有已立项的项目和里程碑
- **操作步骤：**
  1. 创建里程碑，计划完成日期为 2026-09-01
  2. 当前日期为 2026-10-01（已超过计划日期）
  3. 不填写实际完成日期
  4. 手动将状态改为"已延期"
- **预期结果：**
  - 里程碑状态显示为"已延期"
  - 延期原因可填写
- **测试方式：** 手动验证（注：自动标记延期需在查询时动态判断或通过定时任务实现）

## 四、权限测试

### T23：项目负责人越权访问

- **前置条件：** 用户 A（项目负责人，负责项目 X），项目 Y 由用户 B 负责
- **操作步骤：**
  1. 以用户 A 登录
  2. 在项目库列表中尝试打开项目 Y 的详情页
- **预期结果：**
  - 用户 A 在项目库列表中看不到项目 Y（或能看到基本信息但无法打开详情）
  - 只有管理员能看到项目 Y 的完整信息
- **测试方式：** 手动验证

### T24：技术评审人只能评审分配给自己的项目

- **前置条件：** 技术评审人 A，有待评审项目 X（分配给评审人 A）和项目 Y（分配给评审人 B）
- **操作步骤：**
  1. 以评审人 A 登录
  2. 查看待办列表
- **预期结果：**
  - 待办中只有项目 X
  - 看不到项目 Y 的待办
- **测试方式：** 手动验证

### T25：管理员全局可见

- **前置条件：** 项目管理员登录
- **操作步骤：**
  1. 以管理员登录
  2. 进入"项目库"页面
  3. 查看列表和统计
- **预期结果：**
  - 能看到所有项目（包括所有状态）
  - 能进行所有操作（新建、编辑、删除）
  - 统计数据准确
- **测试方式：** 手动验证
