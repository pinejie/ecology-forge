# 脏数据清理规则

> 最后更新：2026-07-27

---

## 核心原则

不随便试。先在开发设计里把参数确认好，再直接执行正式步骤。能减少 80% 的脏数据。

## 处理规则

| 场景 | 处理方式 |
|------|---------|
| SDK 调用成功，数据有效 | 保留，是正式数据 |
| SDK 调用失败，参数错误 | 不产生脏数据，修正后重试 |
| 表单建了一半需要重建 | 先删失败的表单，再重建 |
| 测试数据验证用 | 表名加 `_test` 后缀，验证完直接 drop |
| 中途失败导致数据不完整 | 清理这步产生的数据，记录原因，等用户指示 |

## 清理方法

- **建模引擎表单**：通过 OA API 或 MCP `deleteform` 接口删除
- **数据库表**：`DROP TABLE uf_xxx_test`
- **模块**：通过 MCP `update_module` 或 OA 管理后台删除

## 记录要求

每次清理都要在 `04-执行记录.md` 中记录：
- 清理了什么
- 为什么清理
- 清理结果
