# 场景定位规范

> 拿到需求后，第一步是判断需求属于哪个能力域。判断结果决定后续走哪套推导规则。

---

## 一、场景识别表

| 关键词/描述 | 能力域 | 典型场景 |
|------------|--------|---------|
| "表单"、"字段"、"增删改查"、"查询列表"、"浏览框"、"菜单"、"发布"、"编辑"、"停用"、"查看" | **建模引擎** | 项目申报、合同管理、宿舍登记、通知公告 |
| "审批"、"流程"、"节点"、"流转"、"会签"、"转交"、"驳回"、"签字" | **流程引擎** | 请假审批、报销流程、采购审批 |
| "移动端"、"H5"、"小程序"、"企微"、"钉钉" | **移动建模** | 移动端填报、企微消息推送 |
| "定时"、"轮询"、"自动执行"、"计划任务"、"每天"、"定期" | **定时任务** | 每日统计、过期自动处理、定时通知 |
| 以上多种混合 | **多域混合** | 带审批的表单系统、移动端审批 |

---

## 二、判断逻辑

按以下顺序判断：

1. **扫描需求关键词** — 对照场景识别表，命中哪个域
2. **判断是否混合** — 如果需求同时涉及多个域，标记为"多域混合"
3. **多域拆分** — 混合场景按域拆分为独立的子需求，每个子需求独立走后续流程

---

## 三、各能力域特征

### 建模引擎

**核心特征**：结构化数据存储 + 页面展示（增删改查）

**判断标志**：
- 需求中提到"管理"某种数据（项目、合同、通知等）
- 需要创建、编辑、查看、删除记录
- 需要列表页面浏览和筛选数据
- 需要菜单入口进入功能页面

**典型输出**：表单、模块、查询列表、浏览框、菜单

### 流程引擎

**核心特征**：多角色审批 + 状态流转

**判断标志**：
- 需求中提到"审批"、"审核"、"批准"
- 有多个角色参与（提交人、审批人、抄送人）
- 有状态流转（草稿→待审批→已通过→已驳回）
- 需要签字意见、审批记录

**典型输出**：流程定义、流程节点、审批规则

> 注：流程引擎目前在 OA 管理后台手动配置，不支持自动化创建。

### 移动建模

**核心特征**：移动端适配

**判断标志**：
- 需求明确提到"手机端"、"H5"、"小程序"
- 需要在移动端填报或查看数据

**典型输出**：移动端布局配置

### 定时任务

**核心特征**：周期性自动触发

**判断标志**：
- 需求中提到"每天"、"定期"、"自动"执行某操作
- 需要过期处理、定时统计、定时通知

**典型输出**：定时任务配置

> 注：定时任务泛微原生支持有限，复杂场景需自行开发。

---

## 四、不支持的能力

| 需求类型 | 原因 | 替代方案 |
|---------|------|---------|
| 移动端原生 App | 泛微只有 H5 移动端 | 用 H5 页面适配 |
| 复杂报表导出 | 泛微报表功能有限 | 导出到 Excel 后处理 |
| 实时推送通知 | 泛微无 WebSocket 推送 | 用定时任务轮询 |

---

## 五、输出要求

场景定位完成后，输出：

```
【场景定位】
- 需求概述：{一句话描述}
- 判定能力域：{建模引擎 / 流程引擎 / 多域混合}
- 判定依据：{命中了哪些关键词}
- 如为多域混合：拆分为 {子需求1} + {子需求2}，分别处理
```
