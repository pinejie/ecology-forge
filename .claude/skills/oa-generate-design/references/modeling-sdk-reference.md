## 1. 应用（App）

### 1.1 modeling_create_app — 创建应用

**参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| app_name | string | 是 | 应用名称 | `"项目管理"` |
| parent_id | int | 否 | 上级应用 ID，不传则为顶级 | `0` |

**思考点 — 应用规划**：

应用是功能分组容器，模块、查询、浏览框都必须属于某个应用。

**创建前回答**：
1. **要不要新建？** 检查已有应用是否可复用（`modeling_list_apps`）
2. **叫什么？** 通常与需求中的功能模块名一致，如"项目管理"、"合同管理"
3. **建几个？** 需求中多个功能属于同一系统时放同一个应用；不同业务域分开建

**命名原则**：
- 用业务语言，不用技术术语
- 简洁明了，如"项目管理"而非"项目管理系统v1"

**决策流程**：列出需求中的所有功能 → 判断是否同一业务域 → 决定应用数量和名称

**依赖**：无（顶层容器）
**产出**：app_id
**验证**：`modeling_list_apps` 确认创建成功

## 2. 表单（Form）

### 2.1 form_create_form — 创建表单

**参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| form_name | string | 是 | 表单中文名 | `"项目申报"` |
| app_id | int | 是 | 所属应用 ID | `45` |
| table_name | string | 否 | 物理表名，不传则自动生成 | `"uf_project_apply"` |
| fields | array\<object\> | 否 | 字段定义列表 | 见下方 |

**fields 结构**：

| 字段 | 类型 | 必填 | 说明 | 取值范围 |
|------|------|------|------|---------|
| name | string | 是 | 英文字段名 | `"project_name"` |
| label | string | 是 | 中文标签 | `"项目名称"` |
| type | string | 是 | 逻辑字段类型 | 见下方"各类型必填参数"，完整清单见 `references/field-type-reference.md` |
| length | int | 否 | text 类型长度 | `200`，默认 `100` |
| db_type | string | 否 | 数据库字段类型（覆盖默认） | `"varchar(200)"` / `"decimal(15,2)"` |
| browser_id | int | 否 | 系统浏览框 ID（type=browser 时） | `1`=人员，`4`=部门 |
| browser_name | string | 否 | 自定义浏览框名称（type=browser 时） | `"项目浏览框"` |
| options | array\<string\> | 否 | 选择框选项（type=dropdown/radio/multiselect 时） | `["选项1", "选项2"]` |

**各类型必填参数**：

| 类型 | 必填参数 | 物理存储 | 说明 |
|------|---------|---------|------|
| text | `length` | varchar(N) | 默认 100 |
| integer | 无 | int | - |
| float | 无 | decimal(38,2) | 可用 `db_type` 覆盖精度 |
| amount | 无 | decimal(15,2) | 金额，带中文大写转换 |
| amount-format | 无 | varchar(30) | 金额千分位显示 |
| textarea | 无 | text | 可选 `html_editor`=true 切富文本 |
| browser | `browser_id` 或 `browser_name` | int/varchar | 二选一；可选 `is_tree`、`is_multi` |
| checkbox | 无 | char(1) | 存 0/1 |
| dropdown | `options` | int | 下拉选择，选项以整数索引存储 |
| radio | `options` | int | 单选按钮 |
| multiselect | `options` | text | 多选 |
| file | 无 | text | 可选 `image`=true 切图片模式 |
| date | 无 | char(10) | SDK 自动转 browser(id=2)，日期选择器 |
| datetime | 无 | varchar(20) | SDK 自动转 browser(id=290) |
| time | 无 | char(5) | SDK 自动转 browser(id=19) |
| year | 无 | int | SDK 自动转 browser(id=178) |
| special | 无 | varchar(4000) | 一般不用 |
| pubchoice | 无 | integer | 一般不用 |

> **注意：** type 字段只接受上表中的逻辑类型，传物理类型（如 varchar、int）会报错。完整说明和物理存储对应关系见 `references/field-type-reference.md`。

**思考点 — 表单设计**：

表单是数据骨架，定义字段和物理存储表。

**创建前回答**：
1. **叫什么？** 表单名称用业务语言，如"项目申报"、"合同登记"
2. **属于哪个应用？** 必须指定 app_id
3. **需要哪些字段？** 根据业务场景列出完整字段清单
4. **哪些字段依赖浏览框？** 分析浏览框依赖，判断是否存在环形依赖

**字段分析**：

根据业务场景推断字段的逻辑类型，参考 `references/field-type-reference.md` 的"业务场景 → 逻辑类型速查"：

| 逻辑类型 | 业务场景 | 关键参数 |
|---------|---------|---------|
| text | 短文本（姓名、编码、电话等） | length |
| textarea | 长文本（备注、描述、说明等） | - |
| integer | 整数（数量、次数、人数等） | - |
| float | 浮点数、金额 | db_type（如需覆盖精度） |
| dropdown | 固定选项下拉（分类、状态等） | **options（必传）** |
| browser | 选择人员/部门/自定义数据 | browser_id 或 browser_name |
| date | 日期 | - |
| checkbox | 是否、有无（二元开关） | - |
| file | 文件/图片上传 | - |

**字段命名原则**：
- 字段名用英文、语义明确
- 创建字段时必须提供完整定义（name、label、type，以及各类型对应的必填参数），禁止依赖 SDK 自动推断
- 自定义浏览框字段必须跳过，等浏览框创建后补加

**决策流程**：确定业务实体 → 列出字段清单 → 判断字段类型 → 分析浏览框依赖 → 处理环形依赖 → 输出字段定义

**依赖**：app_id
**产出**：form_id
**验证**：`form_list_form_fields` 确认字段数量和类型正确

### 3.2 browser_create_browser — 创建自定义浏览框

**参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| browser_name | string | 是 | 浏览框名称 | `"项目浏览框"` |
| form_id | int | 是 | 数据源表单 ID | `123` |
| app_id | int | 是 | 所属应用 ID | `45` |
| fields | array\<object\> | 是 | 浏览框字段配置 | 见下方 |
| default_filter | string | 否 | 默认过滤条件（SQL WHERE）。**值必须与数据库实际存储类型一致**，见下方"选择框字段存储机制" | `"project_status<>0"` |
| page_size | int | 否 | 分页大小 | `10`，默认 `10` |

**fields 结构**：

| 字段 | 类型 | 必填 | 说明 | 取值范围 |
|------|------|------|------|---------|
| fieldname | string | 是 | 字段名 | `"project_name"` |
| istitle | int | 否 | 是否为链接字段 | `0` 或 `1`，默认 `0` |
| isquery | int | 否 | 是否为查询字段 | `0` 或 `1`，默认 `0` |
| displayorder | int | 否 | 显示顺序 | 从 `0` 开始 |
| colwidth | int | 否 | 列宽 | `0`=自适应 |

**思考点 — 浏览框设计**：

创建前分析以下配置：

| 配置项 | 规则 |
|--------|------|
| 名称 | 与关联表单名称一致 |
| 数据源 | 绑定表单（formid）和应用（appid） |
| 默认过滤 | 是否需要预过滤。**生成前必须查数据库确认字段类型**，见下方"选择框字段存储机制" |
| 展示字段 | 核心辨识字段，不贪多（3-5 个） |
| 链接字段（istitle） | 文本类型，唯一，选最代表性的，只能有 1 个 |
| 展示顺序 | 核心辨识在前，辅助在后 |
| 查询字段（isquery） | 能缩小范围的开启，开关类一般不开 |
| 排序 | 日期类降序看最新，名称类升序好找 |

**default_filter 生成规则**：

default_filter 是 SQL WHERE 条件，必须符合 SQL 规范。生成前必须先查数据库确认字段的实际存储内容——浏览框存的是关联 ID，选择框存的是整数序号，不是业务中文名。AI 分析出的业务条件（如"只展示已立项的项目"）必须根据数据库实际存储值转换成 SQL，禁止直接用业务中文名作为 SQL 条件值。

**决策流程**：确定数据源 → 分析字段角色 → 选定链接字段 → 排列展示顺序 → 选定查询条件 → 设定排序 → **查库确认 default_filter 中字段的实际存储值** → 输出结构化配置。

**依赖**：form_id（数据源表单必须先创建）
**验证**：`browser_list_browsers` 确认创建成功

## 4. 模块（Module）

### 4.1 module_create_module — 创建模块

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| module_name | string | 是 | 模块名称 | `"项目申报"` |
| form_id | int | 否 | 关联表单 ID | `123` |
| app_id | int | 否 | 所属应用 ID | `45` |

**思考点 — 模块设计**：

模块是卡片页载体，用户点"新增/编辑/查看"时看到的单条数据页面。创建时自动产生三种布局（查看/新建/编辑）+ 9 条默认权限。

**创建前回答**：
1. **关联哪个表单？** 模块必须关联一个主表单
2. **叫什么？** 模块名称遵循"表单名 + 业务含义后缀"
3. **建几个？** 默认每个表单至少一个模块；若同一表单有不同用途（如评审、归档），可建多个

**命名原则**：
- 首个模块与表单同名，如"项目申报"
- 后续模块加后缀体现用途，如"项目申报-评审"、"项目申报-归档"
- 创建前确认名称是否已存在（`module_list_modules`）

**决策流程**：确定关联表单 → 判断是否需要多模块 → 命名 → 检查是否已存在 → 创建

**依赖**：form_id
**产出**：module_id
**验证**：`module_list_modules` 确认

## 5. 布局配置（Layout）

### 5.1 layout_generate_layout_json — 生成布局配置

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| form_id | int | 是 | 表单 ID | `123` |
| config | object | 是 | 布局配置 | 见下方 |

**config 结构**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| groups | array\<object\> | 是 | 分组列表 |
| groups[].group_name | string | 是 | 分组名称 |
| groups[].fields | array\<string\> | 是 | 包含的字段名列表 |
| groups[].required_fields | array\<string\> | 否 | 必填字段列表 |

**思考点 — 布局分组**：

- **必须分组**，不允许平铺
- 字段 ≤10 个时 1 组叫"基础信息"
- \>10 个时按业务拆分，每组 ≥2 字段，最多 5 组
- **第 1 组固定**叫"基础信息"，放核心识别字段
- **第 2~5 组**按业务重要性从高到低排列
- **组内排序**按业务重要性，常用核心字段排上面，辅助字段排下面

**必填判定**：

| 状态 | 判定标准 |
|------|---------|
| **必填** | 不填会影响后续流转——流程依赖此值、关联字段需带出数据、财务字段影响计算 |
| **编辑** | 可改但不强制（默认状态） |

标注必填时必须给出理由——"不填会导致什么业务问题"。

**示例**：
```json
{
  "groups": [
    {
      "group_name": "基础信息",
      "fields": ["project_name", "project_code", "project_type"],
      "required_fields": ["project_name", "project_type"]
    },
    {
      "group_name": "时间信息",
      "fields": ["start_date", "end_date"],
      "required_fields": ["start_date"]
    }
  ]
}
```

## 6. 查询（Query）

### 6.1 list_create_query — 创建查询列表

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| query_name | string | 是 | 查询名称 | `"项目申报列表"` |
| module_id | int | 是 | 所属模块 ID | `89` |
| description | string | 否 | 描述 | |

**思考点 — 查询设计**：

查询是列表页载体，用户打开菜单第一眼看到的表格。

**创建前回答**：
1. **属于哪个模块？** 查询必须属于某个模块
2. **叫什么？** 查询名称遵循"模块名 + 含义后缀"
3. **建几个？** 默认每个模块至少一个查询；若不同角色需要不同列表（如申报人看自己的、管理员看全部），可建多个

**命名原则**：
- 首个查询直接用模块名，如"项目申报"
- 后续查询加后缀体现用途或角色，如"项目申报列表（科技部）"、"项目申报列表（申报人）"
- 用业务语言，不用技术术语

**决策流程**：确定所属模块 → 判断是否需要多查询 → 命名 → 创建

**依赖**：module_id
**产出**：query_id

## 9. 字段联动（Field Linkage）

### 9.1 fieldlinkage_create_linkage — 创建联动规则

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| module_id | int | 是 | 模块 ID | `89` |
| source_field | string | 是 | 源字段名 | `"person_id"` |
| target_fields | array\<object\> | 是 | 目标字段配置 | 见下方 |
| sql | string | 是 | 查询 SQL | |

**target_fields 结构**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| fieldname | string | 是 | 目标字段名 |
| column | string | 是 | SQL 结果列名 |

**思考点 — 联动判定**：

字段联动是"选 A 自动带出 B、C"的功能。当用户在表单中选择某个字段时，自动从数据库查询数据并填充到其他字段。

**创建前回答**：
1. **源字段是什么？** 选值型字段（如浏览框、下拉框）
2. **要联动哪些目标字段？** 源字段值变化后需要自动填充的字段
3. **能查到吗？** 源字段值类型与目标表主键对得上，且目标字段能通过 SQL 查到

**联动判定原则**：
- 源字段必须是选值型（浏览框、下拉框等）
- 源字段值类型必须与目标表主键匹配
- 目标字段必须能通过 SQL 从目标表查到
- **查得到就做，查不到就不做，不硬凑**

**决策流程**：识别选值型字段 → 判断能否联动 → 确定目标字段 → 编写 SQL → 创建联动规则

**示例**：
- 源字段：项目浏览框（存储 project_id）
- 目标字段：项目负责人、项目开始日期
- SQL：`SELECT project_manager, start_date FROM uf_project WHERE project_id = @project_id`
