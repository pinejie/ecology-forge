# 测试数据清理规则

> 测试数据即时清理，不污染正式环境。

## 核心原则

**测试数据加标记。** 所有测试插入的数据、表单、配置都加 `_test` 后缀或专门标记，便于识别和清理。

**用完即清。** 每条用例跑完就清理，不堆积到最后。

**正式数据不动。** 执行阶段已经确认保留的正式数据，测试阶段只读不写。

## 清理规则

| 数据类型 | 清理方式 | 说明 |
|---------|---------|------|
| 测试记录 | `DELETE FROM table WHERE id IN (...)` | 知道 ID 的直接删 |
| 测试表单 | 查带 `_test` 的表单名 → 删除 | 命名时就加标记 |
| 测试模块 | 查带 `_test` 的模块名 → 删除 | 同上 |
| 测试布局 | 查对应 formid 的 layout → 删除 | 跟表单联动 |
| 临时配置 | 恢复原始配置值 | 改回去，不删 |

## 清理时机

- **每条用例完成后**：立即清理本用例产生的测试数据
- **全部用例完成后**：做一次全面检查，确保无残留
- **修正重跑时**：先清理上次的测试数据，再重新插入

## 报告记录

```markdown
- 清理测试模块 Z 个

```
