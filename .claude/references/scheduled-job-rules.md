# 定时任务编码规范

> 规范泛微 e-cology 定时任务（CronJob）的编写方法论。

---

## 1. 类结构规范

### 1.1 继承要求

- 必须继承 `weaver.interfaces.schedule.BaseCronJob`
- 包名规范：`com.engine.interfaces.sj.zhongda.job.模块名`
- 必须提供无参构造方法
- 实现 `void execute()` 方法（无参数、无返回值）

### 1.2 生命周期

- 构造方法：任务实例创建时调用，禁止在此执行耗时操作
- execute()：定时调度入口，所有业务逻辑在此实现

---

## 2. 数据库操作规范

### 2.1 RecordSet 使用原则

- 统一使用 `weaver.conn.RecordSet` 进行数据库操作
- 优先使用参数化查询（`?` 占位符），禁止字符串拼接 SQL
- 查询前必须确认表结构，禁止猜测列名
- 必须进行空值检查和异常处理

### 2.2 批量操作规范

- 循环中单条 SQL 操作数据量超过 1000 条时，必须分批处理
- 每批处理 1000-5000 条，避免事务过大
- 大数据量操作必须记录进度日志

### 2.3 建模引擎表单插入规范

往 `uf_` 开头的表插入数据时：
- 必须动态查询 `formmodeid`，禁止硬编码
- 查询方式：`SELECT DISTINCT formmodeid FROM uf_xxx WHERE formmodeid > 0`
- 插入时必须包含 `formmodeid` 字段

---

## 3. 日期时间处理规范

### 3.1 SimpleDateFormat 线程安全

- 禁止将 `SimpleDateFormat` 定义为类成员变量
- 必须使用局部变量或 `ThreadLocal` 包装
- 原因：SimpleDateFormat 非线程安全，多线程环境下会产生错误结果

### 3.2 日期计算原则

- 使用 `Calendar` 进行日期加减运算
- 统一使用服务器时区，避免时区混乱
- 日期格式化必须明确指定格式（如 `yyyy-MM-dd`）

---

## 4. 异常处理规范

### 4.1 强制要求

- `execute()` 方法必须用 `try-catch` 包裹所有业务逻辑
- 禁止向外部抛出异常，必须在内部处理
- 异常必须记录日志（使用 `log.error()`）
- 日志必须包含异常堆栈信息

### 4.2 事务处理

- 定时任务没有自动事务回滚机制
- 多步操作必须在代码中做好异常处理
- 关键操作失败时，必须记录失败状态供后续排查

---

## 5. 日志规范

### 5.1 Logger 使用

- 使用 `weaver.integration.logging.Logger`
- 定义方式：`private static final Logger log = LoggerFactory.getLogger(类名.class);`

### 5.2 日志级别

| 级别 | 使用场景 |
|------|----------|
| INFO | 任务开始/结束、关键节点、处理数量统计 |
| WARN | 数据异常但可继续、跳过某些记录 |
| ERROR | 任务失败、严重异常、需要人工介入 |
| DEBUG | 详细调试信息（生产环境通常关闭） |

### 5.3 日志内容要求

- 任务开始必须记录日志
- 任务结束必须记录处理结果（成功/失败、处理数量）
- 关键业务节点必须记录日志
- 异常必须记录完整堆栈

---

## 6. 数据模型规范

### 6.1 模型类定义方式

- 简单场景：使用内部类（推荐）
- 复杂场景：定义独立的模型类
- 模型类必须包含完整的 getter/setter 方法

### 6.2 数据封装原则

- 从数据库查询的数据必须封装到模型对象
- 禁止在业务逻辑中直接使用 `RecordSet` 取值
- 提高代码可读性和可维护性

---

## 7. 常见业务模式

### 7.1 先删后插模式

适用场景：全量数据同步
- 先清理目标表的旧数据（按条件删除）
- 查询源数据
- 批量插入新数据
- 必须保证幂等性（可重复执行）

### 7.2 增量同步模式

适用场景：大数据量增量更新
- 记录上次同步时间（通过日志表或字段标记）
- 只查询变更数据（`modifiedate > lastSyncDate`）
- 判断数据是否存在，存在则更新，不存在则插入
- 记录本次同步时间和处理数量

### 7.3 状态标记模式

适用场景：逐条处理业务数据
- 查询待处理数据（`status=0`）
- 逐条处理，成功标记 `status=1`，失败标记 `status=2`
- 失败时必须记录错误信息
- 统计成功/失败数量

---

## 8. 强制规则

### 8.1 数据库操作

- 查询表结构信息时，必须通过 MCP Server 连接数据库
- 优先使用参数化查询
- 字符串拼接时必须处理 null 和特殊字符
- 禁止在循环中执行大量单条 SQL

### 8.2 代码质量

- 必须进行空值检查
- 必须进行异常处理
- 必须记录关键操作日志
- SimpleDateFormat 必须用局部变量或 ThreadLocal
- 任务必须具备幂等性（可重复执行不产生副作用）

### 8.3 性能要求

- 避免在循环中查询数据库
- 大数据量操作必须分批处理
- 长时间运行的任务必须记录进度日志
- 避免在任务中创建大量对象（考虑对象复用）

---

## 9. 部署与配置

### 9.1 编译部署流程

1. Java 文件放入项目对应包路径
2. 编译生成 class 文件
3. 将 class 文件放入 `classbean/` 目录
4. 重启 e-cology 服务或热加载

### 9.2 定时任务配置

在 e-cology 后端维护中心配置：
- 任务名称：清晰描述任务功能
- 任务类名：完整类路径（如 `com.engine.interfaces.sj.zhongda.job.hrm.XxxJob`）
- Cron 表达式：按业务需求设置执行频率
- 启用状态：确认无误后启用

### 9.3 Cron 表达式规范

- 避免在整点执行（如 `0 0 * * * ?`），建议错峰（如 `0 5 * * * ?`）
- 高频任务（每分钟）必须评估系统负载
- 工作日任务使用 `MON-FRI` 限制
- 长时间运行的任务避免与其他任务时间冲突

---

## 10. 设计原则

### 10.1 幂等性原则

- 任务可以重复执行，不会产生重复数据或副作用
- 先删后插：每次执行先清理旧数据
- 状态标记：通过状态字段避免重复处理
- UPSERT：使用 MERGE 语法或先查后插

### 10.2 健壮性原则

- 所有外部输入必须校验
- 所有数据库操作必须 try-catch
- 关键操作失败必须有降级方案
- 必须记录详细的错误日志供排查

### 10.3 可观测性原则

- 任务开始/结束必须记录日志
- 处理数量必须统计并记录
- 异常必须记录完整堆栈
- 长时间任务必须记录进度

### 10.4 性能优先原则

- 批量操作优于单条操作
- 避免循环中查询数据库
- 大数据量必须分批处理
- 合理使用索引优化查询

---

## 11. 常见问题处理

### 11.1 任务不执行

排查顺序：
1. 检查任务是否启用
2. 检查 Cron 表达式是否正确
3. 查看日志是否有启动异常
4. 确认 class 文件已正确部署到 classbean
5. 检查类名和包名是否正确

### 11.2 数据重复

解决方案：
- 确保任务具备幂等性
- 先删除旧数据再插入新数据
- 使用唯一索引防止重复
- 通过状态字段标记已处理数据

### 11.3 性能问题

优化方向：
- 大数据量分批处理（每批 1000-5000 条）
- 避免循环中查询数据库（改用批量查询）
- 优化 SQL 查询（添加索引、减少 JOIN）
- 考虑使用存储过程处理复杂逻辑
- 评估是否可以用视图替代定时任务

### 11.4 时区问题

处理原则：
- 统一使用服务器时区
- 日期计算使用 Calendar 而非时间戳
- 注意夏令时影响
- 跨时区场景必须明确时区转换
